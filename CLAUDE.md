# MatchResults — старая версия на Nuxt

Результаты футбольных матчей и таблицы по данным TheSportsDB: Nuxt 4, PrimeVue 4, SCSS. Это легаси-версия, задача — чтобы работала; новую версию на React пишут отдельно, в проекте `match-results`. Больших рефакторингов здесь не предлагать, пути деплоя (`/var/www/matchresults`, процесс pm2 `matchresults`) не трогать.

Здесь только то, чего не видно в коде: команды, факты про API, договорённости и ловушки. Как устроен код, объясняют комментарии в нём. Хронику изменений сюда не писать, а меняя код, править и этот файл в том же коммите.

## Команды

- `npm run dev` — dev-сервер, `.env` читает сам.
- `npm run check` — lint, typecheck и тесты. Его же запускает pre-commit хук — по всему рабочему дереву, а не только по тому, что попадает в коммит.
- Production-сборка локально: `npm run build`, потом `PORT=3001 node --env-file=.env .output/server/index.mjs`. Без `--env-file` нет ключа API, и TheSportsDB отвечает 400.
- Ключ API — `NUXT_THE_SPORTS_DB_API_KEY` в `.env`; у v2 он передаётся заголовком `X-API-KEY`. Ключ API-Football — `NUXT_API_FOOTBALL_KEY`, без него хроника и статистика матча только из TheSportsDB.
- Пуш в `main` — это деплой на прод: GitHub Actions проверяет, собирает, копирует на сервер и перезапускает pm2. Кэш API на проде в памяти, деплой его сбрасывает.

## Данные TheSportsDB

- Статусы: `PEN` — серия пенальти идёт, `AP` — матч завершён по пенальти. Завершённые — `FT`, `AET`, `AP` (`FINISHED_MATCH_STATUSES` в `shared/utils/matches.ts`). Статус не всегда честный: в ЛЧ 2024/25 серии пенальти записаны как `FT` без счёта серии, так же финал Лиги наций 2025 (Португалия – Испания 2:2) — его победителя по данным не узнать. Счёт серии отдаёт только `lookupevent` (`intHomeScoreExtra`) и только у `AP`.
- `strTime` и `dateEvent` в UTC. Время и дату по Москве брать из `strTimestamp` (`formatMoscowTime`, `getMoscowDate`).
- Когда матчей нет, API отвечает `{ Message: 'No data found' }` без поля `schedule`. Сезон закончившегося турнира берётся по последнему сыгранному матчу (`server/utils/theSportsDb.ts`).
- **Коды раундов меняются от сезона к сезону** (базу заполняют добровольцы): раунд плей-офф ЛЧ — 160 в 2024/25 и 32 в 2025/26; в Лиге наций 160 — матч за 3-е место. 1/8 — 16, 1/4 — 125, 1/2 — 150, финал — 200 пока совпадают. Квалификация ЛЧ в 2024/25–2025/26 — раунд 400, в 2026/27 — в раундах 0–3 вместе с первыми турами общего этапа (их отбирает `getLeaguePhaseMatches` по командам). Поэтому сетка и туры опираются на команды и даты, а не на коды раундов.
- **Лига наций**: четвертьфиналы в раунде 0 вместе со стыковыми матчами между дивизионами (2024/25: 4 пары из 14), отличающего поля нет ни в расписании, ни в `lookupevent`. Данные 2022/23 неполные.
- Лиги: туры 1–38/34/30, в туре одинаковое число матчей, расписание всего сезона уже в API. «Длинные» туры — перенесённые матчи (в Бундеслиге 2025/26 у 16 и 17 туров). У МЛС туров до ~51, плей-офф под кодами 125/150/160/200, с перерывом на матчи сборных.
- Готовой таблицы (`lookuptable`) нет у ЛЧ, ЛЕ и Лиги наций — её считает `calculateStandings`, зоны ЛЧ/ЛЕ свои (`getLeaguePhaseZone`, по формату УЕФА с 2024/25).
- Зоны в таблицах лиг из `strDescription`. Серия А, Бундеслига и Лига 1 пишут без турнира, расшифровка в `LEAGUE_ZONE_OVERRIDES` по правилам УЕФА 2024–2027 — **при смене правил проверить**.
- Лента событий (`lookuptimeline`): есть у АПЛ, Ла Лиги, МЛС, Эредивизи, ЛЧ (не у всех матчей). У РПЛ почти пусто с октября 2025 (в 2026/27 — 1 матч из 88), у Саудовской лиги и Бразилии в 2026 тоже: источник перестал присылать. v1 `lookuptimeline` и v2 `lookup/event_timeline` отдают одно и то же, у `livescore` авторов голов нет. Время только целыми минутами (без «90+3»). Имена игроков латиницей. В замене `strPlayer` — ушедший с поля, `strAssist` — вышедший (у API-Football так же: `player` и `assist`); бывает замена без вышедшего.
- Статистика матча (`lookupeventstats`) — там же, где лента, но не у всех матчей с лентой. Названия показателей те же, что у API-Football; значения строками.
- Видеообзор — `strVideo` в `lookupevent`, ссылка на YouTube: есть у АПЛ, Ла Лиги, Серии А, МЛС; у ЛЧ и РПЛ пусто (октябрь 2026). В `href` пускаем только https-ссылки YouTube (`getVideoUrl`).
- Минута идущего матча есть только в v2 `livescore/soccer` (`strProgress`); расписание и `lookupevent` её не отдают, а счёт там отстаёт. `livescore` — все лиги разом (вечером во вторник ~80 матчей), обновляется раз в ~2 минуты (поле `updated` — время Великобритании), минута отстаёт на 2–3. Добавленное время — «45+1», в перерыве статус `HT` и минута 45. Закончившиеся матчи остаются в нём со статусом `FT` около часа, потом пропадают. Что там в серии пенальти (`P`, `PEN`?), не проверено — посмотреть в плей-офф.

## API-Football — запасной источник хроники и статистики

- Нужен там, где у TheSportsDB лента не сходится со счётом (`server/utils/apiFootball.ts`). Номер матча в API-Football TheSportsDB отдаёт сам: `idAPIfootball` у матча. Заголовок ключа — `x-apisports-key`.
- Бесплатный тариф — 100 запросов в день, счётчик обнуляется в 00:00 UTC. Весь сезон (`fixtures?league=…&season=…`) на нём закрыт («try from 2022 to 2024»), а один матч по номеру (`fixtures?id=…`) отдаётся вместе с событиями, составами и статистикой — одним запросом. Если эту лазейку закроют, хроники у этих лиг снова не будет, сайт не сломается.
- Автогол, как и у TheSportsDB, записан на команду, которой засчитан. Названия команд другие («Rubin» вместо «Rubin Kazan») — сторону определять по `teams.home.id`.
- Хроника и статистика сыгранного матча хранятся всегда в хранилище Nitro `data` (на проде — файлы `.data/kv/api-football/match/` рядом с процессом, деплой их не трогает), поэтому каждый матч запрашивается один раз. Неудачи и исчерпанный лимит помнятся только в памяти процесса.
- Запрос `/status` лимит не тратит, но счётчик в нём обновляется с задержкой в пару минут.

## Где что в коде

- `shared/utils/` — общее для сервера и браузера: `bracket.ts` (сетка плей-офф), `rounds.ts` (туры главной и их даты), `matchEvents.ts` (хроника матча), `matchStats.ts`, `standings.ts` (таблицы, зоны), `matches.ts` (статусы, даты по Москве), `competitions.ts` (список турниров: `leaguePhase`, `groupRounds`).
- `server/api/`: `bracket`, `rounds` (туры, текущий тур, дни с матчами), `matches` (тур, даты или, без них, текущий тур), `match/[id]` (+ хроника и статистика из TheSportsDB или API-Football), `live` (счёт и минута идущих матчей лиги, без кэша Nitro: `getLiveMatches` сам ходит в TheSportsDB не чаще раза в 30 с), `standings`, `competitions`, `image` (прокси эмблем).
- `app/`: страницы `index`, `standings` (таблица и сетка), `match/[id]`, `about`. Над матчами и таблицей — `CompetitionBar` (`LeagueSelect` и разделы). Поля «Тур» и «Дата» — `RoundSelect`, `DateSelect` на общем `FilterDropdown`: на компьютере PrimeVue `Popover`, на телефоне `Drawer`. Выбор главной хранится в адресе (`utils/homeQuery.ts`). Лига — `useCompetition`, «сегодня» по Москве — `useMoscowToday`, живой счёт поверх расписания — `useLiveScores` (раз в минуту, пока есть идущий матч).

## Код и стили

- Цвета — только токены из `_variables.scss`, кнопки-пилюли — миксин `pill-button` оттуда же. Стили от телефона к компьютеру: `@media (min-width: $breakpoint-desktop)`, 640px.
- PrimeVue: общие цвета — `definePreset` в `nuxt.config.ts`, там же токены панели, шторки, списка и календаря (`components`). Панели рендерятся в `body`, scoped-стили до них не дотягиваются: что не задать токенами — в нескоупленном блоке `FilterDropdown.vue`.
- Строка матча — одна разметка на телефон и компьютер: `MatchTeam` и `MatchScore` на телефоне с `display: contents` становятся ячейками grid в `MatchItem`. Меняя сетку, менять именованные области во всех трёх файлах.
- Фон страницы на `body`, а `html` белый — ради «резиновой» прокрутки macOS над шапкой. Не переносить.
- Эмблемы — только через `getBadgeUrl` (прокси `/api/image`).
- Сетка плей-офф ЛЧ (960px) шире страницы и прокручивается вбок и на компьютере — так задумано: карточки двухматчевых пар 176px, чтобы читались названия.

## Тесты

- `tests/unit/` — чистые функции, окружение node, импорты явные (`#shared/...`, `~/utils/...`). Настоящие расписания сезонов — `tests/fixtures/`.
- `tests/nuxt/` — компоненты и страницы в настоящем приложении Nuxt (`mountSuspended`, подмена API через `registerEndpoint`, авто-импорты и `useFetch` работают). `.nuxtrc` — служебная пометка test-utils, хранится в git.
- Панели PrimeVue (`Popover`) сообщают об открытии и закрытии и ловят Esc в хуках анимации, а Test Utils подменяет `<transition>` заглушкой — нужен `global: { stubs: { transition: false } }`.
- `mountSuspended` сам не размонтирует страницы прошлых тестов: с общим состоянием (лига) они тоже реагируют — размонтировать в `afterEach`.
- `wrapper.text()` склеивает соседние элементы без пробела — проверять элементы по отдельности.

## Ловушки

- Кэш API в dev лежит на диске (`.nuxt/cache/nitro/handlers/`) и отдаёт старый ответ, пока в фоне считается новый: после правки сервера запросить ещё раз или удалить файл. Если фоновое обновление падает, старый ответ отдаётся бесконечно; старые ответы без новых полей могут уронить страницу.
- Scoped-стили Vue молча выбрасывают селекторы с `*` — писать явный класс.
- Страница собирается раньше, чем переход записан в историю браузера: `history.state.back` читать в `onMounted`.
- Ошибки (404 и др.) Nuxt отдаёт JSON-ом, если в запросе нет `Accept: text/html`: проверять страницу ошибки через `curl -H 'Accept: text/html'`.
- `npm outdated` возвращает код 1, когда есть что обновлять, — это не ошибка.

## Зависимости

- PrimeVue остаётся на 4.x: 5.x перешёл на лицензию PrimeUI (без ключа — баннер «Invalid PrimeUI License»). MIT-альтернатива при необходимости — форк OpenVue (`npx @openvue/migrate`). `@primeuix/themes` 3 требует `@primeuix/styled` 1.x (у PrimeVue 4 — 0.7.x) — тоже не обновлять.
- TypeScript остаётся на 6.x: `vue-tsc` и `nuxt typecheck` не работают с TS 7 (у Go-версии нет JS API компилятора), ждать TS 7.1.
- Node >= 24.15 (требование Nuxt 4.6), в `.nvmrc` — 24.
- `npm audit`: ~14 транзитивных уязвимостей в Nuxt и модуле PrimeVue, чинится только апстримом. `npm audit fix --force` НЕ запускать — откатит Nuxt на 3.7.
- Патч-обновления внутри `^`-диапазонов — `npm update`, затем `npm run check` и `npm run build`. Большой дифф `package-lock.json` сверять по парам «пакет → версия», а не по `git diff`: git показывает переставленные блоки как удалённые.
