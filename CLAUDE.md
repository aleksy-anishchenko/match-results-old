# MatchResults — старая версия на Nuxt

Результаты футбольных матчей и таблицы по данным API-Football (тариф Pro): Nuxt 4, PrimeVue 4, SCSS. Это легаси-версия, задача — чтобы работала; новую версию на React пишут отдельно, в проекте `match-results`. Больших рефакторингов здесь не предлагать, пути деплоя (`/var/www/matchresults`, процесс pm2 `matchresults`) не трогать.

Здесь только то, чего не видно в коде: команды, факты про API, договорённости и ловушки. Как устроен код, объясняют комментарии в нём. Хронику изменений сюда не писать, а меняя код, править и этот файл в том же коммите.

## Команды

- `npm run dev` — dev-сервер, `.env` читает сам.
- `npm run check` — lint, typecheck и тесты. Его же запускает pre-commit хук — по всему рабочему дереву, а не только по тому, что попадает в коммит.
- Production-сборка локально: `npm run build`, потом `PORT=3001 node --env-file=.env .output/server/index.mjs`. Без `--env-file` нет ключа API, и страницы показывают ошибку загрузки.
- Ключ API-Football — `NUXT_API_FOOTBALL_KEY` в `.env`. Ключ TheSportsDB (`NUXT_THE_SPORTS_DB_API_KEY`) код больше не читает.
- Пуш в `main` — это деплой на прод: GitHub Actions проверяет, собирает, копирует на сервер и перезапускает pm2. Кэш API на проде в памяти, деплой его сбрасывает.

## Данные API-Football

- Тариф Pro — 7 500 запросов в день, счётчик обнуляется в 00:00 UTC. Без подписки сайт пуст: на бесплатном тарифе (100 в день) текущий сезон закрыт целиком — расписание и таблицы отвечают «try from 2022 to 2024». Запрос `/status` лимит не тратит, но счётчик в нём обновляется с задержкой в пару минут.
- Клиент — `server/utils/apiFootball.ts`, заголовок ключа — `x-apisports-key`. Кончился лимит — до полуночи UTC не спрашиваем (помнится в памяти процесса). Для турниров не из списка (`getCompetitionSeason`) и номеров не из цифр маршруты API не спрашивают: каждый запрос — из лимита. Когда до конца дня осталось меньше 1 000 запросов (заголовок `x-ratelimit-requests-remaining`), матчи по номеру и живой счёт (`spare`) не запрашиваем: перебор номеров извне не оставит сайт без расписаний и таблиц.
- Сезон — год начала (`leagues?id=…&current=true`): и 2026/27, и МЛС 2026 — это 2026.
- Время — `fixture.timestamp` (секунды Unix): `toUtcTimestamp` делает из него UTC без смещения, как ждут `getMoscowDate` и `formatMoscowTime`.
- Статусы: завершённые — `FT`, `AET`, `PEN` (`FINISHED_MATCH_STATUSES`); `P` — серия пенальти идёт, `PEN` — матч завершён по пенальти (у TheSportsDB было наоборот). Счёт серии — `score.penalty`, в `goals` — голы с дополнительным временем.
- **Раунды текстом.** «Regular Season - 5», «League Stage - 3», «League A - 2» — тур по номеру в конце (`getRoundNumber`); у Бельгии после 30 туров — «Championship Group - 31», «Relegation Group - 31»… с общими номерами. Квалификация ЛЧ/ЛЕ («1st Qualifying Round», «Play-offs») и стыковые матчи Лиги наций («Play-offs A/B») — ни в туры, ни в сетку. Плей-офф — «Round of 16», «Quarter-finals», «3rd Place Final», «Final» (`KNOCKOUT_ROUND`). Названия тоже плавают: раунд плей-офф ЛЧ перед 1/8 — «Knockout Round Play-offs» в 2024/25 и «Round of 32» в 2025/26, хотя пар 8, — поэтому по-русски раунд называется по числу пар. Стыки за место в Бундеслиге и Лиге 1 — «Final». У МЛС первый раунд плей-офф («Round of 16») — серии до двух побед, ничья сразу решается пенальти.
- Лиги: туры 1–38/34/30, расписание всего сезона уже в API. «Длинные» туры — перенесённые матчи (в Бундеслиге 2025/26 у 16 и 17 туров).
- Таблицы — готовые у всех турниров (`standings`). Зоны ЛЧ/ЛЕ свои, по месту (`getLeaguePhaseZone`, по формату УЕФА с 2024/25): описание в API для них не годится. Зоны остальных — из описания места (`description`). Серия А, Бундеслига и Лига 1 пишут без турнира, а у Лиги наций зоны свои: расшифровка в `LEAGUE_ZONE_OVERRIDES` — по правилам УЕФА 2024–2027 и формату Лиги наций 2026/27 (переходный сезон, с 2028/29 три лиги), **при смене правил проверить**. В таблице ЛЧ 2026/27 у «Sabah FC» нет номера команды и эмблемы — её название латиницей.
- Матч по номеру (`fixtures?id=…`) отдаётся вместе с событиями, составами и статистикой — одним запросом. Сыгранный матч через 4 часа после начала, если голы хроники сходятся со счётом, хранится всегда в хранилище Nitro `data` (на проде — файлы `.data/kv/api-football/fixture/` рядом с процессом, деплой их не трогает), без оценок игроков (`players`).
- Составы приходят примерно за 20–40 минут до начала. Имена в составах сокращённые («P. Solari»), в событиях — полные («Pablo Solari»), латиницей. Имена и стадионы бывают с HTML-кодами («Sant&apos;Anna», «Inter&amp;Co Stadium») — их расшифровывает `decodeEntities`. В замене `player` — ушедший с поля, `assist` — вышедший; бывает замена без вышедшего.
- Автогол записан на команду, которой засчитан: сторону определять по `teams.home.id`. Добавленное время — `time.extra` («90+3»).
- Живой счёт — `fixtures?ids=` по номерам матчей страницы, до 20 номеров в запросе: минута — `status.elapsed` и `extra` («45+2»), в перерыве `HT`. По номеру закончившийся матч приходит уже со статусом `FT`, а из `fixtures?live=` он сразу пропадает.
- Названия команд латиницей и не такие, как были у TheSportsDB («Bayern München», «Dynamo»): перевод — словарь по номеру команды (`server/utils/teamNames.ts`), его применяет сервер. Новую команду (повышение, новый еврокубковый сезон) добавлять по `teams.home.id`.
- Эмблемы команд и лиг — `media.api-sports.io`, эмблема лиги — по номеру, без запроса. Эмблемы лиг тёмные на прозрачном фоне: подложка им не нужна. У сборных вместо эмблем флаги.
- Видеообзоров у API-Football нет.

## Где что в коде

- `shared/utils/` — общее для сервера и браузера: `bracket.ts` (сетка плей-офф), `rounds.ts` (туры главной и их даты), `standings.ts` (таблицы, зоны), `matches.ts` (статусы, даты по Москве, сверка голов хроники со счётом), `competitions.ts` (список турниров: номера API-Football, `leaguePhase`).
- `server/utils/`: `apiFootball.ts` (клиент и кэшируемые загрузки: сезон, расписание, таблица, матч, живой счёт; турнир из адреса с сезоном — `getCompetitionSeason`), переводчики ответов в типы страниц — `seasonMatch.ts`, `matchDetails.ts` (хроника, статистика и составы — `matchEvents.ts`, `matchStats.ts`, `lineups.ts`), `leagueTable.ts`, `liveScores.ts`, словарь `teamNames.ts`, `decodeEntities` в `text.ts`.
- `server/api/`: `bracket`, `rounds` (туры, текущий тур, дни с матчами), `matches` (тур, даты или, без них, текущий тур), `match/[id]` (шапка, хроника, статистика, составы — один запрос к API-Football), `live` (счёт и минута матчей по номерам), `standings`, `image` (прокси эмблем). Эмблема лиги — по номеру (`getCompetitionBadge`), без запроса.
- `app/`: страницы `index`, `standings` (таблица и сетка), `match/[id]`, `about`. Над матчами и таблицей — `CompetitionBar` (`LeagueSelect` и разделы). Поля «Тур» и «Дата» — `RoundSelect`, `DateSelect` на общем `FilterDropdown`: на компьютере PrimeVue `Popover`, на телефоне `Drawer`. Выбор главной хранится в адресе (`utils/homeQuery.ts`). Лига — `useCompetition`, «сегодня» по Москве — `useMoscowToday`, живой счёт поверх расписания — `useLiveScores`.

## Код и стили

- Цвета — только токены из `_variables.scss`, кнопки-пилюли — миксин `pill-button` оттуда же. Стили от телефона к компьютеру: `@media (min-width: $breakpoint-desktop)`, 640px.
- PrimeVue: общие цвета — `definePreset` в `nuxt.config.ts`, там же токены панели, шторки, списка и календаря (`components`). Панели рендерятся в `body`, scoped-стили до них не дотягиваются: что не задать токенами — в нескоупленном блоке `FilterDropdown.vue`.
- Строка матча — одна разметка на телефон и компьютер: `MatchTeam` и `MatchScore` на телефоне с `display: contents` становятся ячейками grid в `MatchItem`. Меняя сетку, менять именованные области во всех трёх файлах.
- Фон страницы на `body`, а `html` белый — ради «резиновой» прокрутки macOS над шапкой. Не переносить.
- Эмблемы — только через `getBadgeUrl` (прокси `/api/image`).
- Сетка плей-офф ЛЧ (960px) шире страницы и прокручивается вбок и на компьютере — так задумано: карточки двухматчевых пар 176px, чтобы читались названия.

## Тесты

- `tests/unit/` — чистые функции, окружение node, импорты явные (`#shared/...`, `~/utils/...`, серверные — относительным путём). Настоящие ответы API-Football, урезанные до нужных полей, — `tests/fixtures/api-football/`: сезоны (`seasons/`), таблицы (`standings/`) и три матча. Тесты сервера подменяют функции Nitro (`useRuntimeConfig`, `$fetch`, `useStorage`) через `vi.stubGlobal`, а `defineCachedFunction` — через `vi.hoisted`: она вызывается при загрузке модуля.
- `tests/nuxt/` — компоненты и страницы в настоящем приложении Nuxt (`mountSuspended`, подмена API через `registerEndpoint`, авто-импорты и `useFetch` работают). `.nuxtrc` — служебная пометка test-utils, хранится в git.
- Панели PrimeVue (`Popover`) сообщают об открытии и закрытии и ловят Esc в хуках анимации, а Test Utils подменяет `<transition>` заглушкой — нужен `global: { stubs: { transition: false } }`.
- `mountSuspended` сам не размонтирует страницы прошлых тестов: с общим состоянием (лига) они тоже реагируют — размонтировать в `afterEach`.
- `wrapper.text()` склеивает соседние элементы без пробела — проверять элементы по отдельности.

## Ловушки

- Кэш API в dev лежит на диске (`.nuxt/cache/nitro/handlers/` и `functions/`) и переживает перезапуск: после правки сервера ответ, сохранённый до неё, живёт до конца своего срока (`maxAge`) — удалить файл. Кэш — только в функциях `apiFootball.ts`, без swr (старый ответ не отдают, пока считается новый); маршруты `/api` без кэша: у `cachedEventHandler` без swr Nitro шлёт браузеру `Cache-Control: max-age`, и браузер сам держит ответ.
- Scoped-стили Vue молча выбрасывают селекторы с `*` — писать явный класс.
- Страница собирается раньше, чем переход записан в историю браузера: `history.state.back` читать в `onMounted`.
- Ошибки (404 и др.) Nuxt отдаёт JSON-ом, если в запросе нет `Accept: text/html`: проверять страницу ошибки через `curl -H 'Accept: text/html'`.
- `npm outdated` возвращает код 1, когда есть что обновлять, — это не ошибка.

## Зависимости

- PrimeVue остаётся на 4.x: 5.x перешёл на лицензию PrimeUI (без ключа — баннер «Invalid PrimeUI License»). MIT-альтернатива при необходимости — форк OpenVue (`npx @openvue/migrate`). `@primeuix/themes` 3 требует `@primeuix/styled` 1.x (у PrimeVue 4 — 0.7.x) — тоже не обновлять.
- TypeScript остаётся на 6.x: `vue-tsc` и `nuxt typecheck` не работают с TS 7 (у Go-версии нет JS API компилятора), ждать TS 7.1.
- Node >= 24.15 (требование Nuxt 4.6), в `.nvmrc` — 24.
- `npm audit`: ~14 транзитивных уязвимостей в Nuxt и модуле PrimeVue, чинится только апстримом. `npm audit fix --force` НЕ запускать — откатит Nuxt на 3.7.
- Патч-обновления внутри `^`-диапазонов — `npm update`, затем `npm run check` и `npm run build`. Большой дифф `package-lock.json` сверять по парам «пакет → версия», а не по `git diff`: git показывает переставленные блоки как удалённые.
